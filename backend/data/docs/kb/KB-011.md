# Printing problems with managed print queues

## Symptoms and scope

Users cannot print, jobs stay in the queue, or output is wrong. Causes include the print server queue, drivers, the device itself and secure release.

This guide covers these known causes:

- Stalled job blocking the print server queue (typical signal: `job status error`)
- Queue still using the previous model's driver (typical signal: `driver mismatch`)
- Secure release service lost connection to the directory (typical signal: `release service directory error`)
- Faulty paper sensor in tray two (typical signal: `error 13.B2`)
- Printer received a new address after the network change (typical signal: `port unreachable`)

Synthetic guidance written for development and evaluation; it is not the approved procedure of any real organisation.

## Before you start

You need operator rights on the print server and access to the printer's admin page. Do not print or forward the content of user documents while troubleshooting.

Record the ticket ID, the affected users or systems, the start time and any recent changes before you act. Do not assume a cause from symptoms alone: match the observed signal to a cause below.

## Diagnostic checks

- **Stalled job blocking the print server queue.** When jobs wait behind one job, open the queue on the print server and look for a job in error at the front.
- **Queue still using the previous model's driver.** If output is garbled from one queue, compare the queue's driver with the printer model installed.
- **Secure release service lost connection to the directory.** When no jobs appear at release, check the release service status and its connection to the directory.
- **Faulty paper sensor in tray two.** If a jam error persists with no paper present, record the error code and check the device service history.
- **Printer received a new address after the network change.** If the printer is offline for everyone, compare the address in the printer's network settings with the port on the print server.

## Resolution steps by cause

### Stalled job blocking the print server queue

1. Find the job in error at the front of the queue.
2. Cancel the stalled job and restart the queue on the print server.
3. Ask users to resend their jobs.
4. Confirm a test page prints.

### Queue still using the previous model's driver

1. Compare the queue driver with the installed printer model.
2. Assign the correct driver to the queue on the print server.
3. Ask users to remove and re-add the printer.
4. Confirm a test page prints correctly.

### Secure release service lost connection to the directory

1. Check the secure release service status.
2. Restore the directory connection following the release service guide.
3. Ask a user to send and release a test job.
4. Confirm jobs appear at release.

### Faulty paper sensor in tray two

1. Record the error code and check the device service history.
2. Raise a hardware service call with the print vendor.
3. Redirect users to the nearest working printer.
4. Confirm the device prints after the vendor repair.

### Printer received a new address after the network change

1. Compare the printer's address with the print server port.
2. Request an address reservation for the printer.
3. Update the print server port to the reserved address.
4. Confirm the queue shows ready and a test page prints.

## Validation and escalation

Confirm a test page prints from the user's device and that the queue is empty.

Escalate to Workplace IT field support for hardware faults, and to Print Services engineering if many queues on a server are affected.

Also escalate when the observed facts match none of the causes above, when a step fails, or when the impact grows while you work. Record each step taken and its result in the ticket.
