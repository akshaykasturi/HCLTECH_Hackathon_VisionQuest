# CRM data synchronisation problems

## Symptoms and scope

Records do not synchronise between the CRM and connected systems, or users cannot see or edit records they expect. Causes include integration users, field mappings, API limits and sharing rules.

This guide covers these known causes:

- Integration user credential expired (typical signal: `INVALID_LOGIN`)
- Field missing from the integration mapping (typical signal: `field not mapped`)
- Daily API request limit exhausted by a new integration (typical signal: `REQUEST_LIMIT_EXCEEDED`)
- Territory assignment not updated after move (typical signal: `insufficient access`)
- Overly broad matching rule blocking saves (typical signal: `DUPLICATES_DETECTED`)

Synthetic guidance written for development and evaluation; it is not the approved procedure of any real organisation.

## Before you start

You need read access to CRM setup and integration logs. Do not export customer records into tickets; reference record IDs only.

Record the ticket ID, the affected users or systems, the start time and any recent changes before you act. Do not assume a cause from symptoms alone: match the observed signal to a cause below.

## Diagnostic checks

- **Integration user credential expired.** When all records stop syncing, check the integration log for login errors and the integration user's status.
- **Field missing from the integration mapping.** If one field fails while records sync, compare the integration mapping with the new fields.
- **Daily API request limit exhausted by a new integration.** When failures come late in the day, check API usage by integration user.
- **Territory assignment not updated after move.** If a user cannot see records, check their role and territory against the sharing rules.
- **Overly broad matching rule blocking saves.** When saves fail for duplicates, review the active matching rule criteria.

## Resolution steps by cause

### Integration user credential expired

1. Confirm login failures for the integration user.
2. Rotate the integration credential through the secrets vault.
3. Resume the integration job.
4. Confirm records synchronise.

### Field missing from the integration mapping

1. Compare the integration mapping with the new fields.
2. Add the field to the mapping through the integration change process.
3. Resync affected records.
4. Confirm the field arrives in ERP.

### Daily API request limit exhausted by a new integration

1. Check API usage by integration user.
2. Ask the owner of the new integration to switch to bulk calls.
3. Reschedule non-urgent sync jobs.
4. Confirm daily usage stays within the limit.

### Territory assignment not updated after move

1. Check the user's role and territory.
2. Submit a territory change request through the access workflow.
3. Ask the user to refresh after the change.
4. Confirm records are visible.

### Overly broad matching rule blocking saves

1. Review the active matching rule criteria.
2. Ask the CRM owner to narrow the rule.
3. Retry saving the record.
4. Confirm the record saves.

## Validation and escalation

Confirm the affected records match in both systems and the integration log shows success.

Escalate to CRM Support engineering if the integration is down for all records or customer data appears in the wrong account.

Also escalate when the observed facts match none of the causes above, when a step fails, or when the impact grows while you work. Record each step taken and its result in the ticket.
