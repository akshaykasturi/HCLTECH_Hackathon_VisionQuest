# Software Center installation failures

## Symptoms and scope

Applications offered in Software Center fail to install, stay in a downloading state, or install but do not start. Causes include content distribution, dependencies, device state and licensing.

This guide covers these known causes:

- Required runtime dependency not installed (typical signal: `0x87D00607`)
- Branch distribution point missing the package content (typical signal: `content not found`)
- Pending restart flag left by an interrupted update (typical signal: `pending reboot`)
- Concurrent licence pool exhausted on the licence server (typical signal: `license pool full`)
- Device marked non-compliant because disk encryption is suspended (typical signal: `compliance: encryption`)

Synthetic guidance written for development and evaluation; it is not the approved procedure of any real organisation.

## Before you start

You need read access to the device management console and client logs. Only install software from the catalogue; never ask the user to install from external sites.

Record the ticket ID, the affected users or systems, the start time and any recent changes before you act. Do not assume a cause from symptoms alone: match the observed signal to a cause below.

## Diagnostic checks

- **Required runtime dependency not installed.** When one package fails quickly, read the application enforcement log on the client for the missing prerequisite.
- **Branch distribution point missing the package content.** If downloads stall at one site, check whether the site's distribution point holds the content for the package.
- **Pending restart flag left by an interrupted update.** If installs report a pending restart after reboots, check the device for an incomplete update that keeps the restart flag set.
- **Concurrent licence pool exhausted on the licence server.** When an installed app refuses to start for licence reasons, check current usage on the licence server compared with the pool size.
- **Device marked non-compliant because disk encryption is suspended.** If apps are blocked for compliance, read the device compliance report to see which setting failed.

## Resolution steps by cause

### Required runtime dependency not installed

1. Read the client log for the prerequisite named in the failure.
2. Install the required runtime from Software Center first.
3. Retry the application install.
4. Confirm the application opens.

### Branch distribution point missing the package content

1. Confirm the content status for the package at the branch distribution point.
2. Ask Endpoint Engineering to redistribute the content to that distribution point.
3. Retry the install on an affected device.
4. Confirm the download completes.

### Pending restart flag left by an interrupted update

1. Check the device for an incomplete update.
2. Complete the update installation from the device management console.
3. Restart the device once the update finishes.
4. Confirm the application install proceeds.

### Concurrent licence pool exhausted on the licence server

1. Check concurrent licence usage on the licence server.
2. Release licences held by devices idle beyond the documented time.
3. Submit a licence purchase request through procurement if usage stays at the limit.
4. Confirm the application starts.

### Device marked non-compliant because disk encryption is suspended

1. Read the failing setting in the device compliance report.
2. Resume disk encryption through the device management console.
3. Trigger a compliance check after encryption resumes.
4. Confirm the application is available to install.

## Validation and escalation

Confirm the application shows as installed in Software Center and opens for the user.

Escalate to Endpoint Engineering if the same package fails on many devices, which points to a package or distribution problem.

Also escalate when the observed facts match none of the causes above, when a step fails, or when the impact grows while you work. Record each step taken and its result in the ticket.
