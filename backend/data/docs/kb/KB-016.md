# SAP ERP transaction failures

## Symptoms and scope

Users cannot complete ERP transactions such as purchase orders, goods receipts or invoice postings. Causes include authorisations, master data, posting periods, workflow and interfaces.

This guide covers these known causes:

- Role missing authorisation for the new plant (typical signal: `authorisation check failed`)
- New posting period not opened (typical signal: `posting period not open`)
- Vendor master record blocked by duplicate check (typical signal: `vendor blocked`)
- Workflow agent assignment broken after organisation change (typical signal: `no agent found`)
- Outbound interface messages failing with partner profile error (typical signal: `IDoc status 02`)

Synthetic guidance written for development and evaluation; it is not the approved procedure of any real organisation.

## Before you start

You need display access in the ERP system and the transaction log. Master data and configuration changes require the data owner's approval. Never use another user's account to test.

Record the ticket ID, the affected users or systems, the start time and any recent changes before you act. Do not assume a cause from symptoms alone: match the observed signal to a cause below.

## Diagnostic checks

- **Role missing authorisation for the new plant.** When a transaction fails for authorisation, read the authorisation check trace for the missing object and value.
- **New posting period not opened.** If postings fail at a month boundary, check which posting periods are open for the company code.
- **Vendor master record blocked by duplicate check.** When one vendor is blocked, read the vendor master change log for who set the block and why.
- **Workflow agent assignment broken after organisation change.** If approvals stall, open the workflow log and check the agent determination step.
- **Outbound interface messages failing with partner profile error.** When orders save but do not reach partners, check outbound message status in the interface monitor.

## Resolution steps by cause

### Role missing authorisation for the new plant

1. Read the authorisation trace for the missing object.
2. Submit a role request for the missing plant authorisation.
3. Ask the user to retry after approval.
4. Confirm the purchase order saves.

### New posting period not opened

1. Check open posting periods for the company code.
2. Ask finance operations to open the new period.
3. Retry the posting.
4. Confirm the document is created.

### Vendor master record blocked by duplicate check

1. Read the vendor master change log.
2. Ask the master data team to review and clear the block if appropriate.
3. Retry the order.
4. Confirm the order is created.

### Workflow agent assignment broken after organisation change

1. Check agent determination in the workflow log.
2. Ask ERP Support to correct the organisation assignment.
3. Restart the workflow items.
4. Confirm approvers receive work items.

### Outbound interface messages failing with partner profile error

1. Check outbound message status in the interface monitor.
2. Correct the partner profile with ERP Support.
3. Reprocess the failed messages.
4. Confirm the supplier portal receives the orders.

## Validation and escalation

Ask the user to repeat the transaction and confirm the document number is created.

Escalate to ERP Support engineering if many users fail the same transaction, or if a period-end close is at risk.

Also escalate when the observed facts match none of the causes above, when a step fails, or when the impact grows while you work. Record each step taken and its result in the ticket.
